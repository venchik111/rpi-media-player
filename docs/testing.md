# Тестирование

Все проверки запускаются без настоящей платы, нужны собранные образы `rpi4` и `qemu`
(см. [Сборка](building.md)).

```bash
scripts/docker.sh scripts/test.sh
```

Запустить один уровень можно так, вместо `audit` подойдут `boot` и `e2e`:

```bash
scripts/docker.sh scripts/test.sh audit
```

## Уровни проверки

| Уровень | Что делает | Что подтверждает |
|---|---|---|
| `audit` | Изучает `sdcard.img`, ничего не запуская | Размер, разделы, файлы загрузки Pi, прошивка Wi-Fi, драйвер под версию ядра, `modprobe` с поддержкой сжатых модулей, нужные программы и права скриптов |
| `boot` | Запускает весь образ в QEMU `raspi4b` с ядром и DTB от Pi | Ядро запускается, разделы монтируются, модули загружаются, службы стартуют, появляется `login:` |
| `e2e` | Запускает разделы образа Pi в QEMU `virt` с виртуальным Wi-Fi | Поведение устройства глазами пользователя, список ниже |

В `virt` используется другое ядро: там нет драйвера Wi-Fi от Pi. Поэтому `boot` проверяет
ядро Pi, а `e2e` проверяет систему и логику.

### Что проверяет `e2e`

- Запускаются все службы, монтируются разделы.
- Имя сети читается из `rpi-player.conf` на разделе `BOOT`, в том числе с переводами строк Windows.
- Точка доступа поднимается, виртуальный клиент подключается по WPA2, получает адрес и забирает плейлист.
- Заливка по SFTP от пользователя `media` сразу попадает в эфир.
- Плейлист живой, номера сегментов растут.
- В сегментах есть H.264 и AAC. Другие форматы видео и звука конвертируются.
- Оборванная заливка не прерывает эфир.
- Файлы автоматически не удаляются.

## Что эти проверки не подтверждают

QEMU `raspi4b` не эмулирует Wi-Fi, Ethernet, USB и аппаратный кодер. Только на настоящей плате
можно проверить:

- работу чипа Broadcom в режиме точки доступа;
- время загрузки и скорость на реальной карте;
- воспроизведение звука на слух и работу с VLC.

## Проверка на настоящей плате

1. Появляется сеть `rpi-cam`.
2. Клиент подключается и получает адрес.
3. В VLC идут полосы «нет сигнала».
4. После заливки своего файла поток переключается на него, и слышен звук.
5. После выключения и включения питания поток возвращается сам.
6. Файл не в H.264 перекодируется.

## Работа с виртуальной платой вручную

```bash
DOCKER_ARGS="-p 2222:2222 -p 8080:8080" scripts/docker.sh scripts/run-qemu-virt.sh
```

Затем в другом окне:

```bash
ssh -p 2222 root@localhost
```

Поток в этом режиме доступен по адресу `http://localhost:8080/stream.m3u8`. Выход из консоли
виртуальной машины: Ctrl-A, затем X.

Запуск образа в эмуляторе Raspberry Pi 4:

```bash
scripts/docker.sh scripts/run-qemu-raspi4b.sh
```
