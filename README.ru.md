# rpi-media-player

[English version](README.md)

## Что это такое

Это готовая «прошивка» (образ системы) для **Raspberry Pi 4B**. Её записывают на
флешку размером от 512 МБ, вставляют в малинку и включают. Дальше всё работает само:

1. Малинка поднимает **свою Wi-Fi сеть** `rpi-cam`. Роутер не нужен, подключаться
   можно прямо к ней, с телефона или ноутбука.
2. По этой сети она отдаёт **видеопоток, как IP-веб-камера**: бесконечно, по кругу
   крутит загруженное тобой видео.
3. Видео заливается на малинку по **SFTP**: это передача файлов по SSH, работает через
   FileZilla, WinSCP или команду `sftp`.

```
телефон/ноутбук ──Wi-Fi "rpi-cam"──▶ Raspberry Pi 4B ──▶ http://192.168.50.1:8080/stream.m3u8
                                            ▲
                              sftp media@192.168.50.1   (залить видео)
```

Открыть поток можно в **VLC** (Медиа → Открыть URL), в Safari на iPhone или просто в
браузере на телефоне: страница `http://192.168.50.1:8080/` со встроенным плеером.

## Словарик

| Термин | Что это значит |
|---|---|
| **Образ** (`sdcard.img`) | Файл, который целиком записывается на флешку. В нём вся система. |
| **Buildroot** | Инструмент, который собирает минимальный Linux из исходников. Благодаря ему образ весит ~470 МБ, а не несколько гигабайт, как Raspberry Pi OS. |
| **Точка доступа (AP)** | Малинка сама раздаёт Wi-Fi, как роутер. Отвечают за это программы `hostapd` (сама сеть) и `dnsmasq` (выдаёт подключившимся IP-адреса). |
| **HLS** | Способ передачи видео по HTTP: поток режется на кусочки по 2 секунды (`.ts`) плюс список этих кусочков (`stream.m3u8`). Так работают многие IP-камеры и онлайн-трансляции. |
| **«Live», как у камеры** | Плейлист всё время обновляется и никогда не «заканчивается». Плеер думает, что смотрит прямой эфир. |
| **SSH / SFTP** | Удалённый доступ к малинке: SSH даёт командную строку, SFTP позволяет передавать файлы. Через SFTP видна вся файловая система. |
| **QEMU** | Эмулятор: запускает систему для ARM-процессора прямо на ПК, без настоящей малинки. |
| **Docker** | Изолированная «коробка» с Linux внутри Windows, в которой идёт сборка и тесты. Ничего не нужно ставить руками. |

## Как это устроено внутри

| Часть | Чем сделано |
|---|---|
| Операционная система | Buildroot 2026.02.3 (LTS), ядро от Raspberry Pi, BusyBox |
| Wi-Fi точка доступа | `hostapd` на встроенном Wi-Fi (`wlan0`) + `dnsmasq` (DHCP). Параметры берутся из `rpi-player.conf` |
| SSH и SFTP | OpenSSH. Ключи сервера хранятся на разделе `data`, поэтому не меняются после перезагрузки |
| Видеопоток | Скрипт `player-ctl` запускает `ffmpeg`. Тот берёт самое свежее видео из `/data/media` и крутит его по кругу в HLS. Отдаёт поток веб-сервер `lighttpd` на порту 8080 |
| Видео ещё нет | Показывается «нет сигнала» (цветные полосы). Можно положить свою картинку `/data/media/placeholder.jpg` |
| Видео не в H.264 | Один раз автоматически перекодируется (сначала аппаратным кодером Pi, если не вышло, то программным `libx264`). Пока идёт перекодирование, показывается «нет сигнала» |

**Разделы на флешке** (всего ~470 МБ, влезает на 512 МБ):

| Раздел | Размер | Что там |
|---|---|---|
| `BOOT` (FAT32) | 64 МБ | Загрузчик, ядро и **`rpi-player.conf`**. Этот раздел виден в Windows, если вставить флешку в ПК |
| `rootfs` (ext4) | 200 МБ | Сама система |
| `data` (ext4) | 200 МБ | Твои видео (`/data/media`) и SSH-ключи |

## Настройка

Все настройки лежат в одном файле **`rpi-player.conf`** на разделе `BOOT`. Вставь флешку
в компьютер, открой этот файл Блокнотом, поменяй нужное и сохрани. Изменения применяются
при следующем включении малинки.

```sh
AP_SSID="rpi-cam"            # имя Wi-Fi сети
AP_PASSPHRASE="camera1234"   # пароль Wi-Fi, от 8 до 63 символов; пусто = открытая сеть
AP_COUNTRY="RU"              # страна (влияет на разрешённые каналы)
AP_CHANNEL="6"               # канал Wi-Fi
AP_ADDR="192.168.50.1"       # адрес малинки в её Wi-Fi сети
HLS_PORT="8080"              # порт видеопотока
MEDIA_FILE=""                # какой файл крутить; пусто = последний загруженный
ROOT_PASSWORD="player"       # пароль root для SSH/SFTP
MEDIA_PASSWORD="media"       # пароль пользователя media для SFTP
```

Если ты уже на малинке по SSH: `mount -o remount,rw /boot`, отредактировать
`/boot/rpi-player.conf`, перезагрузить (`reboot`).

**Значения по умолчанию**

| | |
|---|---|
| Wi-Fi сеть / пароль | `rpi-cam` / `camera1234` |
| Видеопоток | `http://192.168.50.1:8080/stream.m3u8` |
| Страница с плеером | `http://192.168.50.1:8080/` |
| SSH/SFTP | `root` / `player` или `media` / `media` |

> ⚠️ Перед сдачей или реальным использованием **смени пароли** в `rpi-player.conf`.

## Сборка образа

Нужен **Docker Desktop**, на этом компьютере он уже есть. Команды запускаются в **Git Bash**
из папки проекта:

```bash
git clone --recurse-submodules https://github.com/venchik111/rpi-media-player
```

```bash
cd rpi-media-player
```

```bash
scripts/docker.sh scripts/build.sh rpi4
```

Результат: `out/rpi4/sdcard.img`. Для тестов в эмуляторе нужен ещё QEMU-вариант:

```bash
scripts/docker.sh scripts/build.sh qemu
```

Первая сборка идёт 1–2 часа: скачиваются и компилируются компилятор, ядро и ffmpeg.
Всё скачанное кэшируется в Docker-томе `rpi-player-work`, поэтому повторные сборки
занимают минуты.

## Как записать на флешку

1. Скачай и установи **Raspberry Pi Imager**.
2. «Выбрать ОС» → «Use custom» → выбери `out/rpi4/sdcard.img`.
3. Выбери флешку → «Записать».
4. Вставь флешку в Pi 4B, включи питание. Примерно через 20–30 секунд появится Wi-Fi сеть `rpi-cam`.

## Флешка больше 512 МБ: больше места под видео

Образ занимает ~470 МБ и работает на флешке любого размера. Но раздел `data` под
видео фиксированный, **200 МБ** (свободно ~190 МБ, это примерно 5–10 минут 720p).
Остальное место на большой карте остаётся неразмеченным. Чтобы отдать его под
видео, после записи образа растяни раздел `data` до конца флешки через GParted.
Видео и настройки при этом не пропадают.

На Linux (например, Arch):

1. Поставь GParted:
   ```bash
   sudo pacman -S gparted
   ```
2. Вставь записанную флешку в компьютер и запусти:
   ```bash
   sudo gparted
   ```
3. Справа вверху выбери **свою флешку** (например, `/dev/sdb`, ориентируйся по размеру).
   ⚠️ Не перепутай с диском компьютера.
4. Если на разделах стоит значок ключа (раздел смонтирован), щёлкни по каждому
   правой кнопкой → **Unmount**.
5. Правой кнопкой по **последнему** разделу (ext4, метка `data`) → **Resize/Move**.
   Перетащи правый край до конца, чтобы «Free space following» стало 0 → **Resize**.
6. Нажми зелёную галочку **Apply** и дождись окончания.

Без графики то же самое делается двумя командами. `sdX` замени на свою флешку и
трижды проверь букву через `lsblk`:

```bash
sudo parted /dev/sdX resizepart 3 100%
```

```bash
sudo e2fsck -f /dev/sdX3 && sudo resize2fs /dev/sdX3
```

Проверить после загрузки малинки, сколько места под видео: `ssh root@192.168.50.1 df -h /data`.

Если пользуешься Windows, растянуть ext4 штатными средствами нельзя: нужна загрузочная
флешка GParted Live или любая машина с Linux.

## Как залить видео и посмотреть

1. Подключись к Wi-Fi `rpi-cam` (пароль `camera1234`).
2. Залей видео. Вариант для **WinSCP / FileZilla**: протокол SFTP, хост `192.168.50.1`, порт 22,
   логин `media`, пароль `media`, положить файл в папку `/data/media`. Вариант из командной строки:

   ```bash
   sftp media@192.168.50.1
   ```
   и внутри `put movie.mp4`.
3. Открой в VLC: `http://192.168.50.1:8080/stream.m3u8`.

Последний залитый файл начинает играть **автоматически**, перезагружать ничего не нужно.
Посмотреть, что сейчас идёт в эфир: зайди по SSH (`ssh root@192.168.50.1`) и выполни
`player-ctl status`.

## Как проверено без настоящей малинки

Малинки под рукой нет, поэтому образ проверяется на компьютере, в эмуляторе. Проверка
состоит из трёх уровней, и каждый закрывает то, чего не видят остальные:

```bash
scripts/docker.sh scripts/test.sh
```

| Уровень | Что делает | Что доказывает |
|---|---|---|
| **1. Аудит образа** (`audit`) | Заглядывает внутрь `sdcard.img`, ничего не запуская | Образ ≤ 500 МБ. Разделы размечены правильно. На месте все файлы загрузки Pi 4 (`start4.elf`, DTB, `config.txt`). Есть **прошивка Wi-Fi-чипа Pi 4** (`brcmfmac43455`) и драйвер Wi-Fi под именно эту версию ядра. Есть все нужные программы, скрипты запуска исполняемые. |
| **2. Загрузка на «виртуальной Pi 4»** (`boot`) | Запускает весь образ в эмуляторе QEMU `raspi4b`, с **настоящим ядром Pi** | Ядро Pi грузится, все три раздела монтируются, все службы стартуют, появляется приглашение входа `login:`. |
| **3. Сквозной тест** (`e2e`) | Запускает **ровно те разделы, что лягут на флешку**, в эмуляторе с **виртуальным Wi-Fi** (`mac80211_hwsim`) | Тест, как пользователь, меняет имя сети в `rpi-player.conf` (с виндовыми переводами строк), и точка доступа поднимается с этим именем и паролем WPA2. Виртуальный «телефон» подключается к Wi-Fi, получает IP и забирает плейлист. Видео заливается по SFTP и попадает в эфир. Поток живой (номера кусочков растут), кусочки в H.264. Видео не в H.264 перекодируется. |

Почему не всё делается на «виртуальной Pi 4»: эмулятор QEMU для Pi 4 пока не умеет
сеть и Wi-Fi (поддержку ещё только дописывают). Поэтому сетевая часть проверяется на
обычной виртуальной ARM-машине, но с теми же самыми файлами системы.

**Что без железа проверить нельзя никак:**
- Что сам радиочип Broadcom в Pi 4 согласится работать точкой доступа. Связка
  `brcmfmac` + `hostapd` здесь стандартная и на Pi 4 широко используется, а прошивка и
  драйвер в образе проверены аудитом.
- Аппаратный кодер H.264. Если он не заработает, перекодирование автоматически пойдёт
  через программный `libx264`. Для видео, которое уже в H.264 (почти любое `.mp4`),
  кодер вообще не нужен.

Запустить только один уровень:

```bash
scripts/docker.sh scripts/test.sh e2e
```

Поиграться с виртуальной малинкой руками (Ctrl-A, затем X для выхода):

```bash
DOCKER_ARGS="-p 2222:2222 -p 8080:8080" scripts/docker.sh scripts/run-qemu-virt.sh
```

Затем в другом окне подключиться по `ssh -p 2222 root@localhost` или открыть в VLC
`http://localhost:8080/stream.m3u8`.

## Что где лежит в репозитории

```
buildroot/                      Buildroot (подмодуль, зафиксированная версия)
br2-external/                   всё «наше» для Buildroot:
  configs/                        rpi4_player_defconfig (Pi), qemu_player_defconfig (эмулятор)
  board/common/rpi-player.conf    настройки по умолчанию
  board/common/rootfs-overlay/    файлы, которые кладутся в систему:
    etc/init.d/S*                   скрипты запуска (разделы, Wi-Fi, SSH, веб-сервер, плеер)
    usr/sbin/player-ctl             логика видеопотока
  board/rpi4/                     загрузка Pi: config.txt, cmdline.txt, разметка флешки
docker/Dockerfile               окружение для сборки и тестов
scripts/                        build.sh (сборка), test.sh (все проверки), audit-image.sh,
                                run-qemu-virt.sh / run-qemu-raspi4b.sh (эмуляторы)
tests/                          автотесты (Python, pytest)
```

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Не видно Wi-Fi сети | Подожди 30–40 секунд после включения. Проверь `AP_COUNTRY` и `AP_CHANNEL` (для 2.4 ГГц каналы 1–13). Пароль должен быть не короче 8 символов, иначе сеть не поднимется. |
| Сеть есть, поток не открывается | Адрес именно `http://192.168.50.1:8080/stream.m3u8`. Телефон может сам переключиться на мобильный интернет: на Android ответь «Оставаться в сети». |
| Вместо видео полосы «нет сигнала» | Видео ещё не залито, ещё перекодируется или не читается. Подробности покажет `player-ctl status` по SSH. |
| Нужен доступ без Wi-Fi | Воткни кабель в Ethernet-порт: малинка возьмёт адрес по DHCP от роутера, дальше заходи по SSH. |
